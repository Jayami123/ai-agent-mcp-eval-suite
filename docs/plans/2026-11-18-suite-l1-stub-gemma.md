## 4. Design decisions (with reasons)

| # | Decision | Why | Alternative considered |
|---|---|---|---|
| D1 | Stub is a plain `node:http` server with no framework. | Smallest surface; no new dependency; easy to read. | Express/Fastify: adds dependencies for two routes. |
| D2 | **Primary selector: the request header `X-P4-Fixture: <id>`** (Node receives it as `x-p4-fixture`). **Fallback:** a marker `[fixture:<id>]` in a message's `content`, used only when the header is absent. Reviewer answer to Q1. | The header is clean and is not part of the conversation. The marker is a fallback for proxies that drop custom headers. Canonical traces and P4-STAT-001 assertions use `tool_calls` only, never message text. Recorded user-message fields have any marker stripped before an artifact is written (`stripFixtureMarkers`). The Gemma path never uses a marker. | A `model` name per fixture: needs one LiteLLM alias per fixture. |
| D3 | Multi-turn fixtures use a `turns` array. The turn index equals the number of `role: "tool"` messages in the request. | Deterministic, stateless server: no session memory is needed. Repeated identical requests get identical answers. | Server-side session state: makes determinism depend on request order. |
| D4 | Streaming (`"stream": true`) is rejected with HTTP 400. | Keeps the byte-identical check simple. Real streaming is not needed for L1 stub. | Implementing SSE: more code, no L1 benefit. |
| D5 | No new npm dependencies in T1–T5. Hand-written validation of fixtures. | Avoids supply-chain surface before the harness pin exists. | zod (the harness uses zod v4): fine later, not needed for L1 stub. |
| D6 | Harness consumed as an npm git dependency pinned to a tag (section 5). | Matches P1, P5 and P6 (VERIFIED: `#v0.3.0`, `#v0.5.1`, `#v0.2.18` in their `package.json`). | Git submodule and raw checkout: see section 5.2. |
| D7 | `pr.yml` replaces `ci.yml`. | One PR check, not two identical ones. The bootstrap `ci.yml` runs `npm run check` only. **Open question Q2.** | Keep both: duplicate runs, duplicate check names. |
| D8 | Nightly job fails closed (error) when the secret is missing. | The spec forbids silently calling another model. An error is visible; a skip looks green. | Skip with a notice: looks like a pass in the Actions list. |
| D9 | Nightly cron is `30 9 * * *` (09:30 UTC). | 09:30 UTC is 01:30 PST or 02:30 PDT, so it is after Pacific midnight in both seasons. | `0 8 * * *` would be 00:00 PST in winter, which is midnight exactly, not after it. |

### 5.3 Known cost of the npm git dependency (flagged)

- Recorded (reviewer answer, R2): the harness (v0.5.1) has `"prepare": "tsc"`. `dist/` is gitignored in the harness, so a git-dependency install must build it. `typescript` is a harness devDependency, which is what lets `prepare` run. npm runs `prepare` on git installs, so `dist/index.js` is built during a normal `npm ci`.

## 6. The stub server

### 6.1 Endpoints

| Method and path | Behaviour |
|---|---|
| `GET /health` | `200` with body `{"status":"ok"}`. |
| `POST /v1/chat/completions` | Reads the JSON body. Finds the fixture id. Returns one OpenAI-style chat completion. |
| anything else | `404` with `{"error":{"message":"not found"}}`. |

Errors (all JSON, all `Content-Type: application/json`):

| Condition | Status | Message (exact) |
|---|---|---|
| Body is not valid JSON | 400 | `request body is not valid JSON` |
| `stream` is `true` | 400 | `streaming is not supported by the p4 stub` |
| Neither `X-P4-Fixture` header nor a marker found | 400 | `no fixture id in X-P4-Fixture header or [fixture:<id>] message marker` |
| Header is present but empty or fails the id pattern | 400 | `invalid fixture id` |
| No header, and more than one distinct marker id in messages | 400 | `more than one fixture id in messages` |
| Fixture id fails the id pattern | 400 | `invalid fixture id` |
| Fixture file does not exist | 404 | `unknown fixture id: <id>` |
| Fixture file is invalid | 500 | `invalid fixture: <id>: <reason>` |
| Turn index past the end of `turns` | 409 | `turn <n> is past the end of fixture <id>` |
| Body larger than 1 MiB | 413 | `request body too large` |

"Fail loudly" means: the stub never returns a default answer for an unknown id. The error is also logged to stderr.

### 6.2 Fixture file format

File: `src/stub/fixtures/<id>.json`. The file name (without `.json`) must equal the `id` field.

Id pattern: `^[a-z0-9][a-z0-9-]{0,63}$`. This blocks path traversal (`../`).

```json
{
  "id": "smoke-search-001",
  "description": "Fake data only. One search tool call, then a final text turn.",
  "turns": [
    {
      "tool_calls": [
        { "name": "search_records", "arguments": { "query": "fake-alpha", "limit": 5 } }
      ]
    },
    { "content": "Found the fake record." }
  ]
}
```

Rules for `turns`:
- At least one turn.
- Each turn has **exactly one** of: `tool_calls` (non-empty array) or `content` (string).
- `tool_calls[i].name` is a non-empty string. `arguments` is a JSON object.

Example request that selects this fixture (fake content). Primary: header.

```
POST /v1/chat/completions
X-P4-Fixture: smoke-search-001
Content-Type: application/json

{"model":"p4-stub","messages":[{"role":"user","content":"Search for fake-alpha."}]}
```

Fallback (only when the header is absent; for proxies that drop headers):

```json
{
  "model": "p4-stub",
  "messages": [
    { "role": "user", "content": "[fixture:smoke-search-001] Search for fake-alpha." }
  ]
}
```

### 6.3 Response shape

Turn index = number of messages with `role` equal to `"tool"` in the request. For the first request it is `0`.

Response body (all keys sorted by `canonicalJson`, so bytes are stable):

```json
{
  "choices": [
    {
      "finish_reason": "tool_calls",
      "index": 0,
      "logprobs": null,
      "message": {
        "content": null,
        "role": "assistant",
        "tool_calls": [
          {
            "function": { "arguments": "{\"limit\":5,\"query\":\"fake-alpha\"}", "name": "search_records" },
            "id": "call_smoke-search-001_0_0",
            "type": "function"
          }
        ]
      }
    }
  ],
  "created": 0,
  "id": "chatcmpl-smoke-search-001-0",
  "model": "p4-stub",
  "object": "chat.completion",
  "usage": { "completion_tokens": 0, "prompt_tokens": 0, "total_tokens": 0 }
}
```

`created` is fixed at `0` on purpose. A real timestamp would break byte-identical comparison.

For a `content` turn: `finish_reason` is `"stop"`, `content` is the string, and there is no `tool_calls` key.

### 6.4 Skeleton: `src/stub/canonical.ts`

```ts
/** Stable JSON: object keys sorted recursively. Arrays keep their order. */
export function canonicalJson(value: unknown): string {
  return JSON.stringify(sortKeys(value));
}

function sortKeys(value: unknown): unknown {
  if (Array.isArray(value)) {
    return value.map(sortKeys);
  }
  if (value !== null && typeof value === "object") {
    const out: Record<string, unknown> = {};
    for (const key of Object.keys(value).sort()) {
      out[key] = sortKeys((value as Record<string, unknown>)[key]);
    }
    return out;
  }
  return value;
}
```

### 6.5 Skeleton: `src/stub/fixtures.ts`

```ts
import { existsSync, readFileSync } from "node:fs";
import path from "node:path";

export interface ToolCallSpec {
  name: string;
  arguments: Record<string, unknown>;
}

export interface TurnSpec {
  tool_calls?: ToolCallSpec[];
  content?: string;
}

export interface Fixture {
  id: string;
  description: string;
  turns: TurnSpec[];
}

export const FIXTURE_ID_PATTERN = /^[a-z0-9][a-z0-9-]{0,63}$/;

/** Fallback marker. Global flag: use with matchAll. Never used for traces or assertions. */
export const FIXTURE_MARKER = /\[fixture:([^\]]*)\]/g;

/** Removes fixture markers from text before it is written to any recorded artifact. */
export function stripFixtureMarkers(text: string): string {
  return text.replace(FIXTURE_MARKER, "").trim();
}

export class FixtureNotFoundError extends Error {}
export class FixtureInvalidError extends Error {}

/** Loads and validates one fixture. Throws FixtureNotFoundError or FixtureInvalidError. */
export function loadFixture(fixturesDir: string, id: string): Fixture {
  if (!FIXTURE_ID_PATTERN.test(id)) {
    throw new FixtureInvalidError("invalid fixture id");
  }
  const file = path.join(fixturesDir, `${id}.json`);
  if (!existsSync(file)) {
    throw new FixtureNotFoundError(`unknown fixture id: ${id}`);
  }
  const raw: unknown = JSON.parse(readFileSync(file, "utf8"));
  return validateFixture(raw, id);
}

export function validateFixture(raw: unknown, expectedId: string): Fixture {
  const fail = (reason: string): never => {
    throw new FixtureInvalidError(`invalid fixture: ${expectedId}: ${reason}`);
  };
  if (typeof raw !== "object" || raw === null) fail("not an object");
  const obj = raw as Record<string, unknown>;
  if (obj["id"] !== expectedId) fail("id does not match file name");
  if (typeof obj["description"] !== "string") fail("description must be a string");
  const turns = obj["turns"];
  if (!Array.isArray(turns) || turns.length === 0) fail("turns must be a non-empty array");
  for (const turn of turns as unknown[]) {
    if (typeof turn !== "object" || turn === null) fail("turn must be an object");
    const t = turn as Record<string, unknown>;
    const hasCalls = t["tool_calls"] !== undefined;
    const hasContent = t["content"] !== undefined;
    if (hasCalls === hasContent) fail("each turn needs exactly one of tool_calls or content");
    if (hasCalls) {
      const calls = t["tool_calls"];
      if (!Array.isArray(calls) || calls.length === 0) fail("tool_calls must be a non-empty array");
      for (const call of calls as unknown[]) {
        const c = call as Record<string, unknown>;
        if (typeof c["name"] !== "string" || c["name"] === "") fail("tool call name must be a non-empty string");
        if (typeof c["arguments"] !== "object" || c["arguments"] === null || Array.isArray(c["arguments"])) {
          fail("tool call arguments must be a JSON object");
        }
      }
    } else if (typeof t["content"] !== "string") {
      fail("content must be a string");
    }
  }
  return raw as Fixture;
}
```

### 6.6 Skeleton: `src/stub/server.ts`

```ts
import { createServer, type IncomingMessage, type Server, type ServerResponse } from "node:http";
import { canonicalJson } from "./canonical.js";
import { FIXTURE_ID_PATTERN, FIXTURE_MARKER, FixtureInvalidError, FixtureNotFoundError, loadFixture, type Fixture } from "./fixtures.js";

export interface StubOptions {
  fixturesDir: string;
  /** Use 0 in tests to get an ephemeral port. The server never picks a non-loopback address. */
  port: number;
}

const MAX_BODY_BYTES = 1024 * 1024;
export const FIXTURE_HEADER = "x-p4-fixture"; // Node lowercases incoming header names

export function createStubServer(opts: StubOptions): Server {
  return createServer((req, res) => {
    handle(opts, req, res).catch((err: unknown) => {
      sendJson(res, 500, { error: { message: String(err) } });
    });
  });
}

async function handle(opts: StubOptions, req: IncomingMessage, res: ServerResponse): Promise<void> {
  if (req.method === "GET" && req.url === "/health") {
    sendJson(res, 200, { status: "ok" });
    return;
  }
  if (req.method !== "POST" || req.url !== "/v1/chat/completions") {
    sendJson(res, 404, { error: { message: "not found" } });
    return;
  }

  const bodyText = await readBody(req);
  if (bodyText === null) {
    sendJson(res, 413, { error: { message: "request body too large" } });
    return;
  }

  let body: { stream?: unknown; messages?: unknown; model?: unknown };
  try {
    body = JSON.parse(bodyText) as typeof body;
  } catch {
    sendJson(res, 400, { error: { message: "request body is not valid JSON" } });
    return;
  }
  if (body.stream === true) {
    sendJson(res, 400, { error: { message: "streaming is not supported by the p4 stub" } });
    return;
  }

  const messages = Array.isArray(body.messages) ? (body.messages as Array<Record<string, unknown>>) : [];
  const headerValue = req.headers[FIXTURE_HEADER];
  let id: string;
  if (headerValue !== undefined) {
    // Primary selector. When the header is present, messages are not consulted.
    id = typeof headerValue === "string" ? headerValue.trim() : "";
  } else {
    // Fallback only when the header is absent (some proxies drop custom headers).
    const ids = new Set<string>();
    for (const message of messages) {
      const content = typeof message["content"] === "string" ? message["content"] : "";
      for (const match of content.matchAll(FIXTURE_MARKER)) ids.add(match[1] ?? "");
    }
    if (ids.size === 0) {
      sendJson(res, 400, { error: { message: "no fixture id in X-P4-Fixture header or [fixture:<id>] message marker" } });
      return;
    }
    if (ids.size > 1) {
      sendJson(res, 400, { error: { message: "more than one fixture id in messages" } });
      return;
    }
    id = [...ids][0] ?? "";
  }
  if (!FIXTURE_ID_PATTERN.test(id)) {
    sendJson(res, 400, { error: { message: "invalid fixture id" } });
    return;
  }

  let fixture: Fixture;
  try {
    fixture = loadFixture(opts.fixturesDir, id);
  } catch (err) {
    if (err instanceof FixtureNotFoundError) {
      console.error(err.message);
      sendJson(res, 404, { error: { message: err.message } });
    } else if (err instanceof FixtureInvalidError) {
      console.error(err.message);
      sendJson(res, 500, { error: { message: err.message } });
    } else {
      throw err;
    }
    return;
  }

  const turnIndex = messages.filter((m) => m["role"] === "tool").length;
  const turn = fixture.turns[turnIndex];
  if (turn === undefined) {
    sendJson(res, 409, { error: { message: `turn ${turnIndex} is past the end of fixture ${id}` } });
    return;
  }

  const message: Record<string, unknown> = { role: "assistant", content: turn.content ?? null };
  let finish = "stop";
  if (turn.tool_calls) {
    finish = "tool_calls";
    message["tool_calls"] = turn.tool_calls.map((call, i) => ({
      id: `call_${id}_${turnIndex}_${i}`,
      type: "function",
      function: { name: call.name, arguments: canonicalJson(call.arguments) },
    }));
  }
  const response = {
    id: `chatcmpl-${id}-${turnIndex}`,
    object: "chat.completion",
    created: 0,
    model: typeof body.model === "string" ? body.model : "p4-stub",
    choices: [{ index: 0, finish_reason: finish, logprobs: null, message }],
    usage: { prompt_tokens: 0, completion_tokens: 0, total_tokens: 0 },
  };
  sendJson(res, 200, response);
}

function readBody(req: IncomingMessage): Promise<string | null> {
  return new Promise((resolve, reject) => {
    const chunks: Buffer[] = [];
    let size = 0;
    req.on("data", (chunk: Buffer) => {
      size += chunk.length;
      if (size > MAX_BODY_BYTES) {
        resolve(null);
        req.destroy();
        return;
      }
      chunks.push(chunk);
    });
    req.on("end", () => resolve(Buffer.concat(chunks).toString("utf8")));
    req.on("error", reject);
  });
}

function sendJson(res: ServerResponse, status: number, payload: unknown): void {
  const text = canonicalJson(payload);
  res.writeHead(status, { "content-type": "application/json", "content-length": Buffer.byteLength(text) });
  res.end(text);
}
```

Note: the `turn.tool_calls` call inside `handle` uses `turn.content ?? null` for the message; a `tool_calls` turn has no content so `content` becomes `null`, as in section 6.3.

Note on `{ error: { message } }` for 413: the 413 path destroys the request; the response may not reach some clients. This is acceptable for L1. **UNVERIFIED** that a client sees the 413 body; test with the negative test in T2 only for status code if needed.

### 8.1 P4-STAT-001 determinism test: `tests/l1/stub-determinism.test.ts`

Skeleton (complete enough to type into a file):

```ts
import { test } from "node:test";
import assert from "node:assert/strict";
import path from "node:path";
import type { AddressInfo } from "node:net";
import { createStubServer } from "../../src/stub/server.js";
import { canonicalJson } from "../../src/stub/canonical.js";

const FIXTURE_ID = "smoke-search-001";
const K = 5; // requirement is at least 3; 5 costs almost nothing
const FIXTURES_DIR = path.resolve(process.cwd(), "src/stub/fixtures");

async function postChat(port: number, fixtureId: string): Promise<string> {
  const res = await fetch(`http://127.0.0.1:${port}/v1/chat/completions`, {
    method: "POST",
    headers: { "content-type": "application/json", "x-p4-fixture": fixtureId },
    body: JSON.stringify({
      model: "p4-stub",
      messages: [{ role: "user", content: "run" }],
    }),
  });
  assert.equal(res.status, 200);
  return await res.text(); // raw bytes as text, compared byte-for-byte
}

test("P4-STAT-001: same fixture, k repeated stub runs, byte-identical tool_calls", async () => {
  const server = createStubServer({ fixturesDir: FIXTURES_DIR, port: 0 });
  await new Promise<void>((resolve) => server.listen(0, "127.0.0.1", () => resolve()));
  const { port } = server.address() as AddressInfo;
  try {
    const rawBodies: string[] = [];
    const traces: string[] = [];
    for (let i = 0; i < K; i++) {
      const raw = await postChat(port, FIXTURE_ID);
      rawBodies.push(raw);
      const parsed = JSON.parse(raw) as { choices: Array<{ message: { tool_calls: unknown } }> };
      traces.push(canonicalJson(parsed.choices[0]?.message.tool_calls));
    }
    for (let i = 1; i < K; i++) {
      assert.equal(traces[i], traces[0], `trace ${i} differs from trace 0`);
      assert.equal(rawBodies[i], rawBodies[0], `raw response ${i} differs from response 0`);
    }
    assert.match(traces[0] ?? "", /"name":"search_records"/);
  } finally {
    await new Promise<void>((resolve) => server.close(() => resolve()));
  }
});
```

Rules:
- The test must fail if any byte differs. Do not normalise, trim or sort the traces to make them pass.
- Do not add retries. A flaky determinism test is a real failure.

### 8.6 Gemma outcome taxonomy (for `record.json`)

Every nightly run writes `evidence/nightly/<run-id>/record.json` with `status` set to exactly one of:

| status | Meaning | Job result |
|---|---|---|
| `pass` | Trial completed; all assertions held. | green |
| `fail` | Trial completed; a real assertion failed (wrong tool, wrong arguments, wrong product state). | red |
| `blocked by provider` | Provider safety filter refused the request (response `finish_reason` is `content_filter`, or the error text names a safety block). Not a fail. | green |
| `partial` | Quota exhausted (HTTP 429 or `RESOURCE_EXHAUSTED`), or the run stopped early with a valid partial record. | green |
| `finding:gemma-tool-calling` | Gemma did not return `tool_calls` on a request that requires them, or the provider says tool calling is not supported for this model. See rule below. | green, plus a finding |

Rules:
- **Gemma tool calling fails** (`finding:gemma-tool-calling`): write a finding and stop. Do not switch models. Do not retry with a different alias. Write the finding text to `docs/findings/l1-gemma-tool-calling.md` in a feat branch PR (the test cannot push). In CI, the finding is kept as an artifact and the job summary says so. **Open question Q4** on whether CI should open that PR itself (recommendation: no; a human commits the finding).
- The test never writes to `main` and never edits the repo in CI.
- Do not classify by string guessing alone. Use the HTTP status and the provider's `finish_reason` first. **UNVERIFIED** how LiteLLM surfaces Gemini safety blocks; check in T9 by reading a real LiteLLM response, and record what you saw.

### 8.7 Pacing for Gemma (rate limits)

Limits from the tracker (owner-supplied; **UNVERIFIED** against the provider's current documentation, check before T7): 30 RPM, 16,000 TPM, 14,400 RPD.

Rules:
- One Gemma request in flight at a time (`serialize heavy cases`).
- A heavy turn is any request that carries `tools` or a long history. Before each heavy turn, wait at least **25 seconds** after the previous heavy turn ended. At 25 seconds the rate is about 2.4 heavy turns per minute, under the 30 RPM limit and inside the 16K TPM budget if a heavy turn is about 6K tokens. **UNVERIFIED** the 6K figure; measure it in T9 and adjust the constant if needed.
- Skeleton:

```ts
export class Pacer {
  private last = 0;
  constructor(private readonly minGapMs: number) {}
  async beforeHeavyTurn(): Promise<void> {
    const wait = this.last + this.minGapMs - Date.now();
    if (wait > 0) await new Promise((r) => setTimeout(r, wait));
  }
  afterHeavyTurn(): void {
    this.last = Date.now();
  }
}
```

- No automatic retry on 429. A 429 is recorded as `partial`.
- The 14,400 RPD limit is a backstop: one nightly job is far below it. Do not add a loop that could exceed it.
