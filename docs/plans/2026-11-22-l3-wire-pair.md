## 2. The harness facts (pinned v0.6.13, tag commit `b33edbf`, read from `node_modules/qa-portfolio-harness`)

- **Pin.** `package.json` names `github:Jayami123/qa-portfolio-harness#v0.6.13`, and the lockfile resolves `b33edbf5e55c80b5bf6b254bbf450ff3ac6efd17`.
- **H9 switch.** `LIBRECHAT_MCP_RECORDING=1`, exact value, otherwise off (`src/config.ts` line 184; `parseMcpRecordingFlag` in
  `src/adapters/librechat-recording.ts` lines 16-21).
- **Route rewrite.** With recording on, each MCP URL becomes `http://mcp-recorder:9100/<server name><original path and query>`
  (`librechat-recording.ts` lines 24-31). The recorder forwards the bytes unchanged.
- **Log lines.** The recorder writes one JSON line per record to stdout (`src/mcp-recorder/main.ts` lines 13-18). A `request` record
  has `server` (the route name), `method`, `path`, redacted `headers` and a redacted `body` (`src/mcp-recorder/proxy.ts` lines
  115-125). A `response` record has `server` and `status` (proxy.ts, the upstream response handler).
- **Where the log is.** `docker logs qa-harness-librechat-mcp-recorder-1`, printed by the adapter (`src/adapters/librechat.adapter.ts`
  lines 198-199; `docker/librechat.recording.compose.yml` line 4).
- **What the log hides.** An `Authorization` header is replaced by `[REDACTED]` with no digest (`src/mcp-recorder/redact.ts` lines
  26-35, `SENSITIVE_NAME` at line 19). Only the MCP session id gets a digest (line 32-33). So the log shows which route a call went to
  and which tool it named, but not which bearer value was sent. This is the gap OAUTH-003 needs closed (section 6).
- **Redaction of bodies.** `redactBody` (`redact.ts` line 97) redacts credential-like JSON keys and bearer strings. Tool names and
  routing fields are kept.
- **Mail.** The Nextcloud Mail app and GreenMail are started by `P4_MAIL=1` (the existing entries set it; see
  `tests/l3/nextcloud/mail.e2e.ts` and `tests/l3/outline/flow-mail.e2e.ts`).

## 6. OAUTH-003 and REL-007: why they are skips

**OAUTH-003 (host, G, OAUTH and WIRE).** The ledger's check is `wire.tokenForServerB(trace) != tokenForServerA`. The recorder cannot
supply it. A bearer is replaced by `[REDACTED]` with no digest (`redact.ts` lines 26-35). The attempt is a plain-gate test that feeds
two different bearers through the harness's own `redactHeaders` and shows the output is the same. The case stays a named skip, with
the harness request in the findings: keep a per-header digest for Authorization, the way the session id already has one
(`redact.ts` lines 22-33). OAuth mode also needs the browser sign-in driver (`docs/findings/l3-oauth-mode.md`, section 5).

**REL-007 (all, G, APPR and RAM5).** A five-server stack is not measured. The pair job measures its own memory, so the RAM5 decision
has a number for two servers. The five-server attempt is not made here, and the findings say so.
